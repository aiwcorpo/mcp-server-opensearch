# AGENTS.md

Read-only MCP server for a self-managed OpenSearch cluster, part of [MCP Platform](https://github.com/aiwcorpo/mcp-platform).
Only the platform gateway calls it (internal JWT, policy data pushed to `/.well-known/mcp-policy-data`); it calls OpenSearch with
each user's own token from the credential broker. It is built on `mcp-platform-starter` (repo `mcp-starter-lib`) and follows
the contracts of `mcp-contracts` (versions in `pom.xml`). README and [CONTRIBUTING.md](CONTRIBUTING.md) hold the details.

## Commands

Maven needs JDK 25. With JDK 21 the build fails with `release version 25 not supported`. On macOS with Homebrew:

```bash
export JAVA_HOME=/opt/homebrew/opt/openjdk@25/libexec/openjdk.jdk/Contents/Home
./mvnw -B verify                    # what GitHub, GitLab and Jenkins run; about 40 s, no Docker, no OpenSearch
./mvnw -B test -pl mcp-app -am -Dtest=ManifestTest -Dsurefire.failIfNoSpecifiedTests=false   # one test class
docker build -t mcp-opensearch:dev .
```

There is no separate lint or format step. ERROR lines in the test output come from negative tests; the exit code decides.

## Layout

- `mcp-core` -> `mcp-application` -> `mcp-integration` (OpenSearch adapter, version probe) -> `mcp-tools` -> `mcp-app` (jar,
  end-to-end tests). Unit tests sit in each module; end-to-end tests with `TestGateway` and `StubBackend` in `mcp-app/src/test`.
- `mcp-app/src/main/resources/mcp/policies/`: Cedar schema and policies, shipped in the manifest.
- `mcp-app/src/test/resources/opensearch-fixtures/`: responses written from the documented 2.19 and 3.x shapes, not recorded
  from a cluster. Do not present them as recorded.
- `mcp-app/target/mcp-manifest.json` is generated by the build; never commit it or edit it by hand.

## Hard rule: the server only reads

- No tool may change data, mappings, settings or cluster state. OpenSearch calls stay on the read endpoints that the Javadoc
  of `OpenSearchAdapter` lists (`_search`, `_doc`, `_mapping`, `_stats`, `_cat/indices`, `_resolve/index`, `_cluster/health`,
  `_validate/query`, plus `GET /` of the version probe). No `_msearch`, `_mget`, scripts, `?q=`, SQL or PPL.
- No tool may accept a raw query, query DSL, API path, SQL or PPL, not even as an optional or "advanced" argument. The server
  builds every request itself from closed, typed arguments (text, level, service, time range, index prefix, index, id).
- A change that needs either of these is out of scope for this repository. Stop and ask a person.

## Other rules

- Tool definitions and the policies are part of the manifest that an administrator approves: a changed tool changes its
  `definitionHash`, a changed policy file changes `policiesHash`, and both need a new approval. Say so in the PR.
- A new tool follows the tool guide linked in CONTRIBUTING.md: closed argument schema, a resource argument or `@ResourceRef`
  on every result element that names an index, a test for each refusal, a row in the README tools table.
- Interface changes (credential type, resource type, audit event) start as a `proposed` entry in `CONTRACT_CHANGES.md` of
  `mcp-contracts` and need a person's approval before code here changes.
- Every index access stays inside the caller's granted prefixes and `MCP_OPENSEARCH_INDEX_PREFIXES`; only concrete index names
  go to `_search`. Text from OpenSearch is untrusted and must never reach the model as instructions.
- Never log tokens, credentials or OpenSearch response bodies; follow the existing `event=... key=value` log style.
- Test methods are camelCase sentences (`withoutJwtEveryMcpRequestIs401`). Tests use `StubBackend` and dummy data only.
- The `dev` profile is for loopback runs; never put it in an env file, a systemd unit, `deploy/` or the image.
- CHANGELOG.md: newest first. 2.0.0 is released (tag `v2.0.0`); put new entries under `## Unreleased` at the top.
- Workflow actions are pinned to full commit SHAs and images (CI, `Dockerfile`) to digests. Keep it that way when bumping.

## Boundaries

Ask a person before: pushing to main, tagging, changing the version in `pom.xml`, running `release.yml`, publishing an image
(images go to `ghcr.io/aiwcorpo` only), or connecting to a real OpenSearch cluster or account. Never commit `.env` files,
`mcp-*.env` files other than the tracked `deploy/` ones, certificates, keys, tokens, `local-gateway.env`, internal host names or IP
addresses.

## Pull requests

One change per PR. Commit subject in English, imperative, up to 72 characters; the body says why, not how it was done. Tests go
in the same commit as the code. `./mvnw -B verify` must pass. Update README and CHANGELOG when a tool, setting or visible
behaviour changes. See [CONTRIBUTING.md](CONTRIBUTING.md).
